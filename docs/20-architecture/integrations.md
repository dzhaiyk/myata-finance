# Внешние интеграции

Приложение — SPA без собственного бэкенда. Единственная серверная часть — Netlify Function для iiko.

| Система | Как подключена | Когда используется | При сбое | Где лежат ключи |
|---|---|---|---|---|
| Supabase (PostgreSQL + PostgREST) | `src/lib/supabase.js`, прямые запросы из браузера | всегда | приложение не работает | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (`.env`) |
| Telegram Bot API | `src/lib/telegram.js`, HTTP POST из браузера | отчёт смены отправлен; расхождение кассы > 1000 ₸; загружена выписка | ошибка глотается (`console.error`), учёт не блокируется | `VITE_TELEGRAM_BOT_TOKEN`, `VITE_TELEGRAM_CHAT_ID` — видны в браузере |
| iiko (iikoServer API, запасной режим iikoCloud) | браузер → `POST /api/iiko` → `netlify/functions/iiko.js` → сервер iiko; клиент `src/lib/iiko.js` | кнопка «Заполнить из iiko» в отчёте смены | кнопка показывает ошибку, поля вводятся вручную | только в панели Netlify: `IIKO_SERVER_URL`, `IIKO_LOGIN`, `IIKO_PASSWORD` или `IIKO_PASS_SHA1`; для iikoCloud `IIKO_API_LOGIN`, `IIKO_API_HOST`; защита `IIKO_PROXY_KEY` + `VITE_IIKO_PROXY_KEY` |
| Kaspi Business | файл Excel, разбор в браузере (`src/lib/categorize.js`, `src/lib/bankImport.js`) | ежедневная загрузка выписки | — | нет ключей |
| Halyk | файл PDF из приложения банка, свой извлекатель текста (`src/lib/pdfText.js`, `src/lib/halykStatement.js`, без внешних библиотек) | ежедневная загрузка выписки | — | нет ключей |

## iiko
- Функция на каждый запрос делает вход → вызов → выход: у iikoServer каждая авторизация занимает слот лицензии, слот освобождается даже при ошибке.
- Белый список действий: iikoServer — `olap`, `olap_columns`, `departments`, `terminals`; iikoCloud — `organizations`, `terminal_groups`, `olap`, `olap_columns`. Открытым прокси функция не является.
- Раскладка OLAP задана в `OLAP_FIELDS` (`src/lib/iiko.js`): дата `OpenDate.Typed`, категория блюда `DishCategory` → отдел, тип оплаты `PayTypes.Combo`, сумма `DishDiscountSumInt`, чеки `UniqOrderId.OrdersCount`. Неопознанные категории и типы оплат попадают в «Прочее».
- Кнопка заполняет только выручку по отделам и типам оплат. Касса, терминалы и изъятия вводятся менеджером — на этом держится сверка.
- Проверка после деплоя: `POST /api/iiko {"action":"departments"}` с заголовком `x-proxy-key`. «iiko не настроен» — переменные не сохранены или сайт не пересобран; «Авторизация iiko не прошла» — неверные логин/пароль/адрес.
- Ответ техподдержки 04.09.2026 (confirmed): адрес сервера `https://too-rim-partners.iiko.it` (https, порт 443, без `/resto`); ограничений по IP нет — облачная функция подходит; на один адрес одна сессия, после запроса обязателен logout (совпадает с уже сделанным auth → вызов → logout); документация — `https://ru.iiko.help/articles/#!api-documentations/olap-otchety-v2`.
- Не получено (блокирует TASK-001): логин и пароль отдельного пользователя интеграции и подтверждение его прав (веб-API + OLAP). Пользователя заводит и права выдаёт бухгалтер или сотрудник с правами системного администратора. Ранее присланный SHA1 остаётся без логина — к какому пользователю он относится, поддержка не сказала.
- SHA1 вручную не считаем: функция хеширует `IIKO_PASSWORD` сама (`createHash('sha1')`, `netlify/functions/iiko.js`). Пароль в онлайн-генераторы (в том числе предложенный поддержкой crypt-online.ru) не вводить — это передача пароля третьей стороне.
- Доступ работает с 05.09.2026 (`IIKO_SERVER_URL`, `IIKO_LOGIN`, `IIKO_PASSWORD` в панели Netlify). Проверено на боевой функции: `departments`, `olap_columns` (258 колонок), `olap` за 24.08.2026.
- Все пять полей из `OLAP_FIELDS` подтверждены: `OpenDate.Typed` («Учетный день»), `DishCategory`, `PayTypes.Combo`, `DishDiscountSumInt` («Сумма со скидкой»), `UniqOrderId.OrdersCount`. Фильтры `OrderDeleted` и `DeletedWithWriteoff` тоже на месте.
- Лучше брать `PayTypes`, а не `PayTypes.Combo`: суммы те же (827 288 ₸ за 24.08), но чек, оплаченный двумя способами, `PayTypes` раскладывает по способам, а `.Combo` сваливает в отдельную строку «Банковские карты, Наличные» (20 745 ₸ за 24.08). Менять — только по решению владельца, см. `docs/10-business/shift/open-questions.md` #8.
- iiko не различает Kaspi и Halyk: безналичные приходят одной строкой «Банковские карты». Разделение эквайринга из iiko получить нельзя.
- Отдел надёжнее брать из склада `Store.Name`, а не из `DishCategory`. За июнь–4 сентября 2026 (71,4 млн ₸): склад заполнен у 100 % строк и принимает ровно три значения — «СКЛАД БАР МЯТА» 42,9 %, «СКЛАД КАЛЬЯН МЯТА» 32,5 %, «СКЛАД КУХНЯ МЯТА» 24,6 %; категория блюда пуста у 17,3 % выручки и даёт лишние значения («вино бокал», «вино бутылка»). Существующий `normalizeDepartment` разбирает имена складов без правок (`/кальян/`, `/бар/`, `/кухн/`). Переход — по решению владельца, вопрос #7 в `docs/10-business/shift/open-questions.md`.
- `DishGroup.TopParent` для отделов бесполезен: почти всё лежит в «Меню Мята».
- `departments` у iikoServer отдаёт XML, а не JSON: `iikoRequest` вернёт `null`, потому что разбирает только JSON. На кнопку это не влияет — `DailyReportPage` зовёт `fetchSales` напрямую, `getDepartments` не используется (мёртвый код, TASK-010).
- Одна сессия на адрес: два одновременных «Заполнить из iiko» могут столкнуться (вторая авторизация не пройдёт или выбьет первую). На практике не проверено.

## Выписки банков
- Конвейер импорта один для страницы «Импорт выписки» и карточки «Выписки банков» в отчёте смены: разбор → правила из базы (`bank_rules`) → правила в коде → дедупликация по `tx_hash` → запись с движением по счёту.
- Полнота файла проверяется: остаток начала + обороты = остаток конца. Файл с расхождением сохраняется с пометкой `review_note` (решение владельца 04.09.2026).
- POS-выписка Halyk (по договору эквайринга) содержит только зачисления; для списаний нужна выписка по счёту.
- Правила категоризации — домен `bank`, `docs/10-business/bank/rules.md`.

## Замкнутый контур (с сентября 2026)
| Звено | Источник 1 | Источник 2 | Где сверяется |
|---|---|---|---|
| Выручка по отделам | iiko | сумма по типам оплат | отчёт смены |
| Карты Kaspi / Halyk | терминалы в отчёте | зачисления в выписке | «Контроль» → Эквайринг |
| Наличные | пересчёт кассы | наличная выручка − изъятия | отчёт смены |
| ФОТ | ведомость | выдачи из кассы + банк | «Контроль» → ФОТ |
| Наличные у учредителей | снятия со счетов | возвраты, ЗП, дивиденды наличными, остаток на 1 января | «Контроль» |
| Остатки счетов | движения в приложении | остаток в выписке | «Счета» |
