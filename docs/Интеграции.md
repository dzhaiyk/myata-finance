# Интеграции: iiko и банки

Документ описывает, что уже работает в приложении и что нужно настроить руками. Актуально на 4 сентября 2026.

## 1. iiko: выручка напрямую из кассы

### Как устроено

Приложение — фронтенд без бэкенда, поэтому пароль iiko нельзя держать в коде: всё, что попадает в сборку, видно любому пользователю сайта. Учётные данные живут в Netlify-функции.

```
Браузер → POST /api/iiko {action, body} → Netlify Function → сервер iiko
```

Файлы: [netlify/functions/iiko.js](../netlify/functions/iiko.js) — прокси, [src/lib/iiko.js](../src/lib/iiko.js) — клиент и раскладка отчёта, маршрут прописан в [netlify.toml](../netlify.toml).

Функция поддерживает два интерфейса iiko и выбирает режим по заданным переменным. Для **iikoServer** (тот, что описан в справке iiko как «iikoServer API») доступны действия `olap`, `olap_columns`, `departments`, `terminals`. Для **iikoCloud** — `organizations`, `terminal_groups`, `olap`, `olap_columns`. Открытым проксёром к произвольному API она не является.

Особенность iikoServer: каждая авторизация занимает слот лицензии, поэтому функция на каждый запрос делает авторизацию, вызов и выход. Слот освобождается даже если запрос упал.

### Что настроить в Netlify

В панели Netlify: Site configuration → Environment variables.

Вариант iikoServer (по документации, на которую вы дали ссылку):

| Переменная | Обязательна | Значение |
|---|---|---|
| `IIKO_SERVER_URL` | да | адрес сервера без `/resto`, например `https://xxxxx-co.iiko.it` |
| `IIKO_LOGIN` | да | логин пользователя iiko с правами на API |
| `IIKO_PASSWORD` | да | пароль этого пользователя; SHA1 функция посчитает сама |
| `IIKO_PASS_SHA1` | вместо пароля | если предпочитаете не хранить пароль — готовый SHA1 |

Вариант iikoCloud (если у вас Transport API, а не серверный):

| Переменная | Обязательна | Значение |
|---|---|---|
| `IIKO_API_LOGIN` | да | apiLogin из личного кабинета |
| `IIKO_API_HOST` | нет | по умолчанию `https://api-ru.iiko.services` |

Общие для обоих вариантов:

| Переменная | Обязательна | Значение |
|---|---|---|
| `IIKO_PROXY_KEY` | желательно | любая случайная строка: без неё функцию сможет дёрнуть любой, кто узнает адрес |
| `VITE_IIKO_PROXY_KEY` | если задан предыдущий | та же строка, попадает во фронтенд |

Ключ вставляйте в панель сами: в переписке и в репозитории его быть не должно. Если ключ уже пересылался в открытом виде, перевыпустите его в iiko.

`IIKO_PROXY_KEY` защищает от постороннего, который наткнулся на адрес функции, но не от того, кто откроет исходники страницы: `VITE_`-переменные видны в браузере. Полноценно закрыть выгрузку продаж можно только после переезда на VPS, когда появится серверная авторизация.

### Как проверить после деплоя

```bash
curl -s -X POST https://<ваш-сайт>.netlify.app/api/iiko -H 'content-type: application/json' -H 'x-proxy-key: <IIKO_PROXY_KEY>' -d '{"action":"departments"}' | head -c 400
```

В ответе должен быть список подразделений. Ошибка «iiko не настроен» означает, что переменные не сохранены или сайт не пересобран после их добавления; «Авторизация iiko не прошла» — неверные логин, пароль или адрес сервера.

### Кнопка в отчёте смены

На странице ежедневного отчёта в блоке «Доходы» появилась кнопка «Заполнить из iiko». Она подставляет выручку по отделам и по типам оплат за дату отчёта. Если поля уже заполнены, приложение спросит подтверждение перед заменой.

Что кнопка **не** заполняет и почему: касса на начало и конец смены, суммы по терминалам, изъятия и инкассация вводятся менеджером. Именно расхождение между iiko и пересчётом кассы и есть предмет сверки; если заполнять обе стороны из одного источника, сверять будет нечего.

### Если названия полей в вашем iiko другие

Раскладка OLAP-отчёта задана в `OLAP_FIELDS` в [src/lib/iiko.js](../src/lib/iiko.js):

| Поле | Значение по умолчанию | Что означает |
|---|---|---|
| `date` | `OpenDate.Typed` | дата открытия заказа |
| `category` | `DishCategory` | категория блюда → отдел |
| `payType` | `PayTypes.Combo` | тип оплаты |
| `sum` | `DishDiscountSumInt` | сумма со скидкой |
| `orders` | `UniqOrderId.OrdersCount` | количество чеков |

Список доступных полей возвращает действие `olap_columns`. Категории блюд и типы оплат приводятся к справочникам приложения по ключевым словам (`normalizeDepartment`, `normalizePaymentType`): всё, что не опознано, попадает в «Прочее», поэтому после первого дня стоит проверить, не осело ли там что-то заметное.

## 2. Выписки банков

Прямой интеграции с банками нет, выписки загружаются вручную на странице «Импорт выписок». Кнопка теперь называется «Загрузить выписку» и принимает и Excel, и PDF.

| Банк | Формат | Что проверяется при загрузке |
|---|---|---|
| Kaspi (ТОО, ИП) | Excel из Kaspi Business | остаток начала + обороты = остаток конца |
| Halyk (ИП) | PDF из приложения Halyk | обороты «Дебет/Кредит» из выписки, остаток начала + обороты = остаток конца |

PDF разбирается в браузере, файл никуда не отправляется. Разбор устроен по координатам текста: колонки определяются по строке заголовка, строка транзакции — по дате в первой колонке, многострочные ячейки склеиваются. Реализация — [src/lib/pdfText.js](../src/lib/pdfText.js) и [src/lib/halykStatement.js](../src/lib/halykStatement.js), внешних библиотек не добавлялось.

Перед сохранением приложение показывает предпросмотр: сколько строк разобрано, сколько дублей пропущено и сходятся ли обороты с самой выпиской. Расхождение выводится жёлтым предупреждением — сохранять такую выписку не нужно, сначала выясните причину.

Для POS-выписки Halyk (та, что по договору эквайринга, а не по счёту) отдельного импорта нет: она содержит только зачисления и не показывает списаний со счёта. Нужна именно выписка по счёту.

## 3. Замкнутый контур с сентября 2026

Каждое звено подтверждается двумя независимыми источниками:

| Звено | Источник 1 | Источник 2 | Где сверяется |
|---|---|---|---|
| Выручка по отделам | iiko | сумма по типам оплат | отчёт смены |
| Карты Kaspi | терминалы в отчёте | зачисления в выписке Kaspi | «Контроль» → Эквайринг |
| Карты Halyk | терминал Halyk в отчёте | зачисления в выписке Halyk | «Контроль» → Эквайринг (по банкам) |
| Наличные | пересчёт кассы | наличная выручка минус изъятия | отчёт смены, расхождение кассы |
| Инкассация | изъятия из кассы | взносы наличных в выписке | «Контроль» → наличные у учредителей |
| ФОТ | ведомость | выдачи из кассы и переводы по банку | «Контроль» → ФОТ |
| Остатки счетов | движения в приложении | остаток в выписке | «Счета» → сверка |

Что нужно делать ежедневно: выгрузить выписки Kaspi (ТОО и ИП) и Halyk и загрузить их в приложение; заполнить отчёт смены, нажав «Заполнить из iiko» и введя кассу, терминалы и изъятия. Страница «Контроль» покажет, где контур разошёлся.

Что закрыть отдельно, чтобы контур сошёлся полностью: списания со счёта Halyk (пока загружены только зачисления POS) и разноска наличных у учредителей.
