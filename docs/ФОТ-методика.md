# Методика расчёта ФОТ «Мята | Platinum 4YOU» — для автоматизации модуля «Зарплаты»

Составлено 03.09.2026 по ведомостям `docs/Accounting/ФОТ/2026/*/ЗП Мята *.xlsx`, файлам «Расчет % по ЗП …», «Продажа кальянов», `Ставки_Мята_15092025.xlsx` и ответам учредителя. Все формулы ниже проверены на реальных цифрах: парсер ведомостей (`fot_parse2.py`) сходится с суммами, внесёнными в приложение за февраль–апрель 2026, до тенге по залу, бару, кухне, кальяну и развозке.

## 1. Период и выплата

| Что | Как сейчас |
|---|---|
| Расчётный период | Половина месяца: 1–15 и 16–конец месяца. Одна ведомость = один лист `1.MM-15.MM` / `16.MM-…` |
| Выплата | Наличными из кассы: 16-го — за 1-ю половину, 1-го — за 2-ю половину |
| Авансы | Ежедневно из кассы; менеджер записывает в отчёт смены (`withdrawals.payroll`, строка с именем сотрудника). В ведомости — сетка авансов по дням, колонка X |
| Выдача остатка | Из кассы («инкассация» с комментарием «зп/аванс/фот») либо из наличных учредителей (снятие со счёта ИП/ТОО → выдача) |
| Техперсонал | В ведомость не входит. Оплачивается ежедневно из кассы (строка «Техперсонал» в авансах отчёта смены), ≈ 350–434 тыс./мес |

Формула строки ведомости: **начислено = смены × оклад + %**, **к выдаче = начислено − авансы**.
Колонки листа: D–S отметки смен по дням (1 = отработал), T = число смен, U = оклад за смену, V = процентная часть, W = начислено, X = авансы (ссылка на сетку авансов ниже), Y = к выдаче.

## 3. Особые случаи, встреченные в ведомостях

- Один человек в двух ролях (Маржан: управляющая + отдельная строка «Админ» со своими сменами) — считаются как две строки.
- Отпуск без содержания (управляющая, май и 1–15 июня 2026) — строка пустая, начисление 0.
- В некоторых файлах колонка «начислено» не пересчитана (кэш формул пуст) — восстанавливается по формуле `смены × оклад + %`.
- Штрафы: по словам учредителя есть в файлах «ЗП Мята»; в ведомостях 2026 отдельной колонки нет — вычитаются вручную из «%» или «к выдаче». Для модуля нужна отдельная колонка «удержания» с комментарием.
- Ведомость не содержит техперсонал, СММ считает как «сотрудника» с фиксом.

## 4. Что нужно модулю «Зарплаты», чтобы считать это автоматически

**Справочник должностей** (`positions`): отдел, оклад за смену, тип бонуса и параметр:
`manager_pct_total` (0,6 %), `admin_pct_shift_days` (1 %), `waiter_service_share` (коэф. 0,5–0,7), `bar_pct_shift_days` (1 %), `kitchen_margin_pct` (2 %, только шеф), `hookah_pool` (1 100 ₸/кальян), `fixed_half_month` (сумма).

**Входные данные за период:**
1. Табель смен по дням (отметки 1/0) — вводит управляющая в приложении (сейчас — колонки D–S ведомости).
2. Три iiko-выгрузки за период (пока нет API — импорт Excel тем же механизмом, что и выписки):
   - «Расчет % по ЗП по офам» → надбавка по официантам;
   - «Расчет % по ЗП по менеджерам/барменам» или общий отчёт продаж по учётным дням и складам → выручка по дням (общая и бар);
   - «Продажа кальянов» по учётным дням → количество кальянов.
   Выручку по дням можно брать и из отчётов смен приложения (`departments` по отделам), но iiko точнее (без скидок, по складам).
3. Закуп кухни за период — уже есть в приложении (банк `cogs_kitchen` + наличные `suppliers_kitchen`).
4. Авансы — уже есть: строки `withdrawals.payroll` отчётов смен по имени сотрудника (модуль уже подтягивает их по имени).

**Алгоритм:** для каждого сотрудника: `смены = Σ отметок`, `оклад_часть = смены × ставка`, `%` по правилу должности из входных данных, `начислено = оклад_часть + %`, `удержания`, `к выдаче = начислено − авансы − удержания`. Итог по отделам записывается в P&L (`payroll_*`) одной строкой на месяц за обе половины; выплата фиксируется как расход кассы (инкассация «зп») или как выдача из наличных учредителей.

**Контур контроля (страница «Контроль»):** начислено по ведомости ↔ выдано из кассы (авансы + инкассация «зп») + безнал; остаток должен совпасть с наличными, снятыми учредителями. Расхождение — деньги вне контура.
