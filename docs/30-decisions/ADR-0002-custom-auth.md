# ADR-0002 · Своя авторизация вместо Supabase Auth

## Контекст
Пользователи — сотрудники заведения без корпоративной почты; подтверждение email и восстановление пароля мешали (миграция 002).

## Варианты
1. Supabase Auth (email + magic link) — плюсы: безопасно из коробки; минусы: email обязателен, лишние шаги для менеджеров.
2. Своя таблица `app_users` с логином и паролем — плюсы: просто, админ создаёт пользователей сам; минусы: пароли хранятся как есть, сессия — только userId в localStorage.

## Решение
Вариант 2 (миграция 002): триггер Supabase Auth удалён, `profiles` остался как наследие, RLS открыт для anon.

## Последствия
- Пароль сравнивается строкой (`src/lib/store.js`), хеширования нет; роль «Админ» определяется по имени роли.
- Права проверяются на клиенте (`hasPermission`), маршруты не защищены правами.
- При переезде на VPS (ADR-0008) — хеширование и серверная проверка.
