# ADR-0001 · SPA без бэкенда, Supabase как единственная база

## Контекст
Проект начинался как MVP для одного заведения силами одного человека; нужен был быстрый старт без серверной разработки.

## Варианты
1. SPA + Supabase напрямую — плюсы: ноль серверного кода, REST из коробки; минусы: логика и права только на клиенте, RLS открыт.
2. Свой бэкенд (Node/NestJS) — плюсы: серверная авторизация и валидация; минусы: время, хостинг, поддержка.
3. Supabase Edge Functions для критичных операций — компромисс, не использован.

## Решение
Вариант 1. Все страницы ходят в Supabase напрямую; расчёты — чистые функции в `src/lib`. Исключение — секреты (iiko), см. ADR-0005.

## Последствия
- Права и валидация — только на клиенте; RLS `USING (true)`; пароли в открытом виде (`docs/20-architecture/security.md`).
- Лимит PostgREST 1000 строк — ADR-0007.
- Для SaaS-версии серверный слой неизбежен — ADR-0008.
