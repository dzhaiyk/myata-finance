# Как хранятся доходы и расходы

Актуально на 4 сентября 2026.

## Три источника, одна структура отчёта

Доходов и расходов в базе нет одной таблицей. Есть три источника, из которых P&L собирается на лету.

| Источник | Таблица | Что хранит | Что даёт в P&L |
|---|---|---|---|
| Смены | `daily_reports` | наличные и выручка за день | выручку по отделам и наличные расходы |
| Банк | `bank_transactions` | каждая операция по счетам | все безналичные расходы и прочие поступления |
| Excel и правки | `pnl_data` | история 2022–2025 и ручные корректировки | заменяет расчёт или добавляется к нему |

### `daily_reports` — смены

Одна строка на день. Всё содержимое лежит в JSONB-поле `data`:

| Ключ | Что внутри | Куда идёт |
|---|---|---|
| `departments[]` | выручка по отделам: Кухня, Бар, Кальян, Прочее | строки «Доходы» в P&L |
| `revenue[]` | та же выручка в разрезе оплат: Наличные, Kaspi, Halyk, Wolt, Glovo, Yandex Eda, Прочее | сверка с отделами, наличная выручка в Cash Flow |
| `terminals{}` | суммы по терминалам, ключ — id счёта-терминала | сверка «терминалы ↔ зачисления банка» |
| `withdrawals{}` | изъятия из кассы шестью группами: `suppliers_kitchen`, `suppliers_bar`, `tobacco`, `payroll`, `other`, `cash_withdrawals` | наличные расходы в P&L и Cash Flow |
| `cash_start`, `cash_end`, `discrepancy` | касса на утро, на вечер и расхождение при пересчёте | контроль кассы |

Тонкости: строка `tobacco` с именем «Аппараты» идёт не в закуп, а в CapEx. В `payroll` в P&L попадает только техперсонал, остальные строки там — авансы, они уменьшают долг перед сотрудником, а не расход месяца. В `cash_withdrawals` инкассация с комментарием про зарплату считается выплатой ЗП, остальная — просто выносом денег.

### `bank_transactions` — банк

Одна строка на операцию выписки.

| Поле | Смысл |
|---|---|
| `transaction_date` | дата операции; по ней считается Cash Flow |
| `amount`, `is_debit` | сумма всегда положительная, направление задаёт флаг |
| `category` | код из справочника `categories` |
| `period_from`, `period_to` | период начисления; по нему сумма делится по месяцам в P&L |
| `account_id` | счёт: Kaspi ТОО, Kaspi ИП, Halyk ИП, депозиты |
| `tx_hash` | защита от повторной загрузки той же выписки |

Категория ставится при импорте: сначала правила из таблиц `bank_rules` и `bank_rule_conditions` (их видно на странице «Импорт выписок»), затем правила в коде `src/lib/categorize.js`. Первое совпавшее правило выигрывает.

Четыре категории в P&L не попадают вообще: `uncategorized`, `internal`, `acquiring_settlement`, `cash_withdrawal`. Это не расходы, а перемещение денег. Зачисления эквайринга не идут в выручку, потому что выручка уже взята из отчётов смен, иначе был бы двойной счёт.

### `pnl_data` — Excel и ручные правки

В одной таблице лежат две разные по смыслу вещи, различаются полем `type`:

- `type = 'historical'` — импорт из Excel за 2022–2025. Эти строки **заменяют** расчёт: если за месяц есть исторические данные и нет ни одного отчёта смены, P&L берёт только их, а банк и касса игнорируются.
- `type = 'expense'` (ручные корректировки) — **прибавляются** к рассчитанной строке. Так внесены ФОТ 2026 по ведомостям, скидка по аренде за февраль и снятие двойной аренды в апреле.

Поля: `year`, `month`, `category` (код строки P&L), `amount`, `description`.

## Как собирается строка P&L

Структура отчёта задана в `src/lib/pnlCompute.js` списком `PNL_STRUCTURE`. У каждой строки есть источник:

| Источник | Смысл | Пример |
|---|---|---|
| `daily:*` | только из отчётов смен | выручка по отделам |
| `bank:код` | только из банка | аренда, налоги, коммуналка |
| `both:код` | касса плюс банк | закуп, хозтовары, прочий доход |
| `calc` | сумма дочерних строк или формула | ФОТ, OpEx, прибыль |

Порядок расчёта месяца:

1. Есть исторические строки и нет смен → берём только их.
2. Иначе: выручка и наличные расходы из смен, безналичные из банка с распределением по периодам.
3. Сверху накладываются ручные корректировки.
4. Считаются группы снизу вверх: подстатьи → группа → OpEx → Расходы → прибыль.

Знаки: по расходным строкам дебет прибавляет, кредит вычитает, поэтому возврат от поставщика уменьшает расход. По доходным строкам наоборот: кредит прибавляет.

Одна и та же функция считает и P&L, и дашборд. Cash Flow считает отдельно и по другому правилу: там важна дата платежа, а не период начисления.

## Чего в базе нет

Наличные у учредителей не являются счётом в приложении: деньги, снятые со счёта, уходят из контура и возвращаются либо взносом наличных, либо выплатой зарплаты. Разница видна на странице «Контроль».
