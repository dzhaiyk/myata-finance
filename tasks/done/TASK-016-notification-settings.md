## Цель — что станет возможным
Переключатели типов уведомлений в «Настройках» действительно включают и выключают
уведомления. Экран перестаёт обещать то, чего в приложении нет.

- Перенос токена бота в базу: RLS открыт, это не улучшение (решение владельца).

## План
1. `src/lib/telegram.js`: дефолты трёх типов, кеш, `loadNotifications` / `saveNotifications`
   / `isNotificationEnabled`. Supabase импортируется лениво — модуль остаётся тестируемым.
2. `store.initialize` грузит настройки уведомлений рядом с часом отсечки.
3. Отправители проверяют тип: `DailyReportPage` (отчёт сдан, расхождение кассы),
   `StatementUploadCard` (импорт выписки).
4. `SettingsPage`: три переключателя со state и кнопкой сохранения; два несуществующих
   убраны; порог в подписи считается из `THRESHOLDS`, а не набран текстом.
5. Bot Token и Chat ID — только для чтения, токен замаскирован, подписано где менять.
6. Тесты на `isNotificationEnabled` и на то, что сохраняются только известные типы.

## Критерии приёмки — проверяемые, по одному на строку
- Выключенный тип не отправляется, включённый отправляется.
- Значения переживают перезагрузку страницы.
- В интерфейсе нет типов, которым нечем сработать.
- Токен не показывается целиком.
- `npm test` и `npm run build` зелёные.

## Тесты

## Итог

загружаются при старте (`store.initialize`), сохраняются кнопкой. Отправители передают

замаскирован. Кнопка «Тест» шлёт через общий отправитель, токен больше не живёт в
состоянии страницы. Подпись порога считается из `THRESHOLDS`. 165 тестов.

игнорирует и не сохраняет обратно, отдельной миграции ради этого не делал.

авторизованный, сам проверить не могу.
