## Цель — что станет возможным
Менеджер не переносит расходы руками: изъятия из кассы, внесённые в iiko за
смену, подставляются в разделы закупа и изъятий отчёта смены, менеджер проверяет
и подтверждает. Контур кассы не меняется: сверка остаётся.

## Что известно (разведка 05.09.2026)
- Отчёт SALES (215 полей) расходов не содержит — проверено по логу поставщика.
- Менеджеры вносят расходы как изъятия из кассы в кассовой смене (ответ владельца).
- По документации iikoServer кассовые смены и их платежи отдаются методами
  `/resto/api/v2/cashshifts/list` и `/resto/api/v2/cashshifts/payments/list` —
  **не проверено**: нужен список полей от поддержки или проба через прокси.
  Ключевой вопрос — есть ли у изъятия комментарий/тип, по которому его можно
  разложить по разделам отчёта (закуп кухня / бар / кальян / авансы / прочее).

## Не входит (out of scope)
- Замена ручного ввода: подстановка с подтверждением (решение владельца).
- Закуп через складские накладные — менеджеры их не ведут.

## Вопросы → ответы владельца (с датой)

- Поля кассовых смен и права пользователя интеграции → **ждёт ответа поддержки**

## План
1. Запрос в поддержку iiko (текст ниже) — поля платежей кассовой смены и права.
2. Прокси: действия `cashshifts` и `cashshift_payments` в белый список функции.
3. `src/lib/iikoCash.js`: чистый разбор платежей → строки разделов отчёта по
   правилу сопоставления (комментарий/тип изъятия → раздел); неопознанное — в
   «Прочие расходы» с пометкой, не теряется. Тесты на фикстуре ответа.
4. Кнопка «Заполнить расходы из iiko» рядом с выручкой; заполненные поля —
   запрос подтверждения (как BR-SHF-016).
5. BR-SHF-021 «Расходы из iiko подставляются, менеджер подтверждает».

## Критерии приёмки
- Изъятие с комментарием «закуп кухня» попадает в раздел закупа кухни суммой из iiko.
- Неопознанное изъятие не теряется — видно в «Прочих расходах» с исходным комментарием.
- Касса после подстановки сверяется как раньше.

## Правка 06.09.2026 — источник данных
Владелец: «расходы из iiko не работают», в консоли `api/iiko` → 404.
Причина: методы `/resto/api/v2/cashshifts/list` и `.../payments/list` я взял из
документации и не проверил на сервере — в этом API их нет. Наша функция отдаёт
наружу статус iiko, поэтому виден 404.

Проверено по рабочей библиотеке-обёртке того же API: есть `api/closeSession/list`,
`api/events/sessions`, `api/v2/reports/olap`; типы отчётов — SALES, TRANSACTIONS,
DELIVERIES, STOCK. Изъятия переведены на OLAP `TRANSACTIONS`: тот же эндпоинт,
что уже работает для выручки. Имена полей запрашиваются у сервера, при отказе —
кандидаты по умолчанию; знак суммы отличает изъятие от внесения. 5 тестов.

**Осталось.** Запустить на дате с операциями и прислать текст плашки: число
операций, сколько подставлено и какие поля отчёта выбраны. По нему закрываем
задачу или правим список кандидатов.
