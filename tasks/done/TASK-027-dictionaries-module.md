## Цель — что станет возможным
Заведение само управляет своими отделами и статьями P&L из интерфейса, в одном
месте, отдельном от настроек. Статьи получают подкатегории.

## Не входит (out of scope)
- Структура P&L и Cash Flow в базе — этапы 2 и 3 ADR-0011.
- Переделка страниц поставщиков, учредителей, счетов, персонала, ролей: они уже
  справочники, в модуль попадают ссылками, а не переписыванием.

## Контекст прочитан
- `docs/30-decisions/ADR-0011-dictionaries-module.md`
- `docs/20-architecture/data-model.md` — `categories` (миграция 008, 026)
- `src/components/DepartmentsSettings.jsx`, `src/components/BrandingSettings.jsx`

## Затронутые правила
- Правило 12 (коды неизменяемы) — распространяется на статьи: код из названия,
  только для чтения.
- BR-RPT-020 (подпись статьи из отдела) — подтверждается, редактируется с экрана.

## Вопросы → ответы владельца (с датой)
- Отдельный модуль вместо «Настроек» → да (05.09.2026)
- Структура в базе, формулы в коде → да (05.09.2026)

- Поставщики, учредители, счета, персонал, роли → остаются на своих местах, в модуле карточки-ссылки (05.09.2026)

## План
1. Миграция 028: `categories.parent_code` (подкатегория ссылается на статью),
   право `dictionaries.view` / `dictionaries.manage` в `ALL_PERMISSIONS`.
2. Раздел «Справочники» в навигации со страницей `DictionariesPage` и вкладками:
   Отделы, Статьи; плюс ссылки на Поставщики, Учредители, Счета, Персонал, Роли.
3. Отделы: `DepartmentsSettings` переезжает из «Настроек» на вкладку без изменений.
4. Статьи: новый экран — список по типу и группе P&L, поля: код (из названия,
   только чтение), название, тип, группа P&L, отдел и шаблон подписи,
   родительская статья, порядок, активность.
5. Карточка заведения (бренд, валюта, пояс) остаётся в «Настройках»: это
   одиночные значения, не список.
6. `src/lib/categoriesDict.js`: загрузка и сохранение статей по образцу
   `departments.js`; чистые помощники — дерево подкатегорий, проверка кода.
7. Тесты на помощников; контрактный тест категорий продолжает сверять коды.

## Критерии приёмки — проверяемые, по одному на строку
- «Справочники» в навигации, «Настройки» больше не содержат отделов.
- Статью можно создать, переименовать, отключить и вложить в родительскую из интерфейса.
- Код статьи создаётся из названия и не редактируется.
- Роль без `dictionaries.manage` видит справочники, но не меняет.
- `npm test` и `npm run build` зелёные.
