## Цель — что станет возможным
Менеджеры отмечают смены в приложении вместо Excel; история за декабрь 2025 –
сентябрь 2026 загружена один раз; табель кормит расчёт зарплаты (ставка × доля).

## Что известно (разведка табеля 05.09.2026)
- 20 листов по полмесяца — совпадает с `payroll_periods` (1 = 1–15, 2 = 16–конец).
- Строка: сотрудник, должность **или процент от продаж** (0.07/0.06/0.05 —
  соответствует `staff.sales_pct_override`), дни с долями 1 / 0.7 / 0.5, итог
  «смены», с января колонка «ШТРАФ», последняя колонка — телефон или «наличка».
- Дефекты файла: неверный месяц в шапке ряда листов, день 12 дважды в мае, лист
  «16.09-30» — копия с днями 1–15. Импорт должен брать даты из имени листа и
  порядка колонок, а не из шапки.
- Имена и телефоны — персональные данные: файл вне репозитория, импорт из
  локальной папки, в тестах — вымышленные фамилии.

## Не входит (out of scope)
- Сам расчёт зарплаты (TASK-011) — табель только даёт смены и штрафы.
- Табель из iiko (смены сотрудников по кассе) — не запрашивалось.

## Вопросы → ответы владельца (с датой)
- Доля смены → ставка умножается на долю (05.09.2026) → BR-PAY
- Объём → импорт истории + экран ввода (05.09.2026)
- Кто заполняет табель → **открыт**, вопрос payroll #12
- Телефон / «наличка» в последней колонке → **открыт**, вопрос payroll #13
- Штрафы отдельной строкой с комментарием → payroll #10, по умолчанию да

## План
1. Миграция: `timesheet_entries` (staff_id, work_date, share NUMERIC(3,2),
   fine NUMERIC, comment, tenant-ready); UNIQUE(staff_id, work_date).
2. `src/lib/timesheet.js`: чистые функции — разбор листа Excel в записи
   (дата из имени листа + порядок колонок, доли, штраф), сопоставление имён с
   `staff` (по имени с ручным подтверждением несовпадений), итоги за период.
   Тесты на вымышленной фикстуре с дефектами реального файла.
3. Импорт: страница «Зарплата → Табель → Импорт Excel»: предпросмотр, несовпавшие
   имена, подтверждение, запись.
4. Экран ввода: период × сотрудники × дни, доля из списка 1 / 0.7 / 0.5,
   штраф с комментарием; права по ответу на #12.
5. `PayrollPage` берёт количество смен из табеля вместо ручного ввода
   (с переключателем на время перехода).
6. BR-PAY: табель — источник смен для расчёта.

## Критерии приёмки
- Импорт всех 20 листов даёт по каждому сотруднику те же «смены», что в Excel.
- Дефектные листы импортируются с датами из имени листа, не из шапки.
- Смена, отмеченная в экране, видна в расчёте зарплаты периода.
