## Цель — что станет возможным
Переименование отдела, строки формы или роли перестаёт молча искажать цифры и права.
Сейчас четыре места определяют смысл сравнением с отображаемым названием: ошибки нет,
результат просто уезжает не туда.

## Не входит (out of scope)
- Справочные таблицы отделов и категорий вместо `CHECK` — TASK-018.
- Вынос порогов и дублей в конфигурацию — TASK-017.
- Локализация, валюта, бренд — TASK-019…021.

## Контекст прочитан
- `docs/30-decisions/ADR-0010-nothing-venue-specific-in-code.md` — правила для нового кода
- `docs/20-architecture/customization.md` — раздел «Сравнения по строкам»
- `docs/10-business/shift/rules.md` — BR-SHF-019 (отдел из склада)

## Затронутые правила
- BR-SHF-019 — подтверждается: отдел определяется кодом, не названием.
- Новых BR не вводится: поведение расчётов не меняется, меняется способ сопоставления.

## План
1. Новый `src/lib/config.js` — единственный источник сопоставления: коды отделов
   (`kitchen`/`bar`/`hookah`/`other`) с их текущими названиями, функция
   `departmentCode(name)`, признак строк, уходящих в CapEx (сейчас «Аппараты»).
2. `src/lib/pnlCompute.js:140-143` и `:159` — звать `config.js` вместо сравнения строк.
   Неопознанное название больше не тонет: функция возвращает признак «не распознано»,
   чтобы вызывающий мог показать предупреждение.
3. `src/pages/CashFlowPage.jsx:100,189` и `src/pages/AnalyticsPage.jsx:137` — те же
   «Аппараты» из одного места вместо трёх копий литерала.
4. Миграция `024_role_is_superuser.sql`: `roles.is_superuser BOOLEAN NOT NULL DEFAULT false`,
   `UPDATE ... SET is_superuser = true WHERE name = 'Админ'`. **Применяется вручную в
   Supabase до пуша кода** — иначе администраторы потеряют доступ.
5. `src/lib/store.js:50,65` и `src/pages/RolesPage.jsx:37,48,81,179` — проверять
   `is_superuser`, а не имя роли.
6. `src/pages/UsersPage.jsx:20,46` — убрать `role_id: 4`; роль по умолчанию берётся
   первой из загруженного списка ролей, при пустом списке форма не отправляется.

## Критерии приёмки — проверяемые, по одному на строку
- Переименование отдела «Кухня» → «Кухня Мята» в отчёте смены не меняет P&L по отделам.
- Переименование строки «Аппараты» не переносит сумму между CapEx и Food Cost.
- Переименование роли «Админ» в базе не отнимает права у её пользователей.
- Создание пользователя не зависит от порядка строк в таблице `roles`.
- «Аппараты» встречаются в коде один раз, а не в четырёх файлах.
- `npm test` зелёный.
